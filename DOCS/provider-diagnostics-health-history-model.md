# Provider Diagnostics And Health History Model

## Purpose

This document defines how M13A should treat provider and AI gateway diagnostics.

External-system diagnostics are operationally meaningful because they affect
what context and advisory support were available. They are not automatically
canonical decision facts.

## State Classes

M13A distinguishes four state classes.

| Class | Meaning | Example |
|---|---|---|
| Ephemeral health | Current reachability or availability state | LiteLLM readiness probe failed |
| Retained diagnostic history | Operational history retained for troubleshooting and operator trust | FMP validation failed at a timestamp |
| Replay-visible context | Historical context captured with an advisory artifact or provider output | Fundamentals used FMP fallback after Alpha Vantage quota failure |
| Canonical event truth | Immutable decision or workflow fact in the Event Ledger | PlanApproved |

Provider health, credential validation, route availability, latency, and quota
state begin as operational diagnostics. They do not become canonical event truth
unless a future ADR explicitly changes that boundary.

## Diagnostic Classes

### Provider Unreachable

Meaning:

- The provider could not be reached at validation or request time.

Recommended visibility:

- operator-visible health state
- last failed timestamp
- safe error category
- affected capability

Default retention:

- retained diagnostic history when generated by an explicit validation or
  provider request
- replay-visible only when attached to a captured provider output, advisory
  artifact, or explicit provenance record

### Credential Invalid

Meaning:

- Credential material exists but the provider rejected it or it failed
  provider-specific validation.

Recommended visibility:

- invalid credential state
- provider id
- affected capabilities
- last validation timestamp
- safe failure reason

Default retention:

- retained diagnostic history
- never expose plaintext secrets

### Route Unavailable

Meaning:

- A configured capability route or AI gateway route alias is unavailable.

Recommended visibility:

- route alias or capability route
- gateway/provider id
- affected advisory task or capability
- fallback route if used

Default retention:

- retained diagnostic history
- replay-visible when an advisory artifact records the route alias or fallback

### Quota Exceeded

Meaning:

- Provider or model route rejected the request because quota, rate limit, or
  entitlement budget was exhausted.

Recommended visibility:

- provider/gateway id
- route alias or capability
- timestamp
- retry guidance when known

Default retention:

- retained diagnostic history
- replay-visible when it affects a captured advisory/provenance artifact

### Fallback Triggered

Meaning:

- Preferred provider or route was skipped and an ordered fallback served the
  capability.

Recommended visibility:

- preferred provider/route
- selected fallback provider/route
- reason category
- timestamp
- affected capability

Default retention:

- retained diagnostic history
- replay-visible as provenance when external context was captured

### Latency Spike

Meaning:

- Provider or gateway response time exceeded the configured threshold.

Recommended visibility:

- provider/gateway id
- route alias or capability
- observed latency
- threshold
- timestamp

Default retention:

- ephemeral unless generated during explicit validation or the latency affected
  an operator-visible request

### Validation Succeeded

Meaning:

- An explicit provider, credential, capability, or gateway validation completed
  successfully.

Recommended visibility:

- provider/gateway id
- capability or route alias
- validation timestamp
- validation target

Default retention:

- retained diagnostic history

### Validation Failed

Meaning:

- An explicit validation failed.

Recommended visibility:

- provider/gateway id
- capability or route alias
- validation timestamp
- safe reason category

Default retention:

- retained diagnostic history

### Replay Nondeterminism Warning

Meaning:

- Replay requires historical provider/gateway context that was not captured and
  cannot be reconstructed from current live providers.

Recommended visibility:

- missing context category
- affected artifact or replay surface
- explanation that live provider calls are not used for historical
  reconstruction

Default retention:

- replay-visible warning generated during replay reconstruction
- not a canonical event unless future event taxonomy changes authorize it

## Retention Rules

Initial M13A retention should be conservative.

- Current health may be ephemeral.
- Explicit validation outcomes should be retained as operational diagnostics.
- Provider/gateway provenance attached to market context or advisory artifacts
  should be replay-visible.
- Missing historical route context should be shown explicitly rather than
  inferred from current configuration.
- No diagnostic class should write to the Event Ledger by default.

## Operator Visibility

Operator-facing diagnostics should show:

- affected provider, gateway, route, or capability
- current state
- timestamp
- safe reason category
- impact on available context
- whether fallback served the request
- whether the operator can continue

Diagnostics should not expose:

- plaintext secrets
- raw provider exception dumps
- stack traces
- hidden scoring or opaque provider ranking

## Replay Rules

Replay must not call live providers or live LiteLLM to reconstruct historical
provider state.

Replay may show:

- captured provider provenance
- captured route alias
- captured underlying provider/model when available
- captured fallback state
- explicit unavailable-state warnings

Replay must not infer historical route state from current configuration.

## Event Taxonomy Implication

TF-F063 does not add event types.

Future event taxonomy changes may be warranted only if provider diagnostics
become durable operational facts with replay requirements that cannot be
satisfied through retained diagnostics or advisory provenance. Until then,
diagnostics remain operational state outside canonical decision truth.

## Authority Boundary

Provider diagnostics and health state may inform the operator. They may not:

- mutate lifecycle state
- approve or reject plans
- execute trades
- become AI decision authority
- silently suppress uncertainty
- be presented as canonical truth
